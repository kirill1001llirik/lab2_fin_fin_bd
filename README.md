# Лабораторная работа: модуль справочников

Разработка выполнена на Python с использованием только стандартной библиотеки:

- `tkinter` - desktop-интерфейс;
- `sqlite3` - встроенная база данных SQLite;
- `datetime`, `decimal`, `calendar` - валидация дат, чисел и календарь.

Установка дополнительных пакетов не требуется.

## Справочники

В работе используются два справочника:

1. **Города** - основной справочник.
2. **Поставщики оборудования** - зависимый справочник, в котором поле `city_id` выбирается из справочника городов.

В пользовательском интерфейсе внутренние идентификаторы не отображаются. Для редактирования и удаления пользователь выбирает строку таблицы, а приложение хранит id внутри.

### Справочник «Города»

| Колонка | Тип | Комментарий |
| --- | --- | --- |
| `city_id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Внутренний id, не показывается пользователю |
| `name` | `TEXT` | Название города |
| `country` | `TEXT` | Страна |
| `foundation_date` | `TEXT` | Дата в формате ISO `YYYY-MM-DD`, в интерфейсе `ДД.ММ.ГГГГ` |
| `population` | `INTEGER` | Целое число |
| `area_km2` | `NUMERIC(12, 2)` | Число с фиксированной запятой |
| `description` | `TEXT` | Многострочное описание |
| `is_deleted` | `INTEGER` | Мягкое удаление |

### Справочник «Поставщики оборудования»

| Колонка | Тип | Комментарий |
| --- | --- | --- |
| `supplier_id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Внутренний id, не показывается пользователю |
| `city_id` | `INTEGER` | Внешний ключ на `cities(city_id)` |
| `name` | `TEXT` | Название поставщика |
| `inn` | `TEXT` | УНП/ИНН |
| `contract_date` | `TEXT` | Дата договора |
| `employees_count` | `INTEGER` | Целое число |
| `annual_budget` | `NUMERIC(14, 2)` | Число с фиксированной запятой |
| `address` | `TEXT` | Многострочный юридический адрес |
| `comment` | `TEXT` | Многострочный комментарий |
| `is_deleted` | `INTEGER` | Мягкое удаление |

## Схема базы данных

СУБД: **SQLite**.

Полная схема находится в файле `schema.sql`. Внешний ключ:

```sql
FOREIGN KEY (city_id) REFERENCES cities(city_id)
    ON UPDATE CASCADE
    ON DELETE SET NULL
```

Физическое удаление из приложения не выполняется: записи помечаются как архивные через `is_deleted = 1`, а перед редактированием или удалением сохраняется снимок в таблицы `city_history` и `supplier_history`.

## Возможности приложения

- выбор справочника из выпадающего списка;
- отображение справочника таблицей;
- сортировка по колонкам с учетом типа данных: числа сортируются как числа, даты - как даты;
- добавление, просмотр, редактирование и удаление записей;
- ввод через однострочные поля, числовые поля, многострочные поля;
- выбор связанного города через выпадающий список;
- выбор даты через календарь и ручной ввод с проверкой невозможных дат;
- мягкое удаление без удаления зависимых данных;
- просмотр истории изменений выбранной записи.

## Запуск

Откройте папку проекта и выполните:

```powershell
python app.py
```

Отдельно создать или обновить базу без открытия окна можно так:

```powershell
python app.py --init-db
```

База данных создается рядом с приложением в файле `reference_module.sqlite3`.

## Проверка

Автоматические проверки обязательных сценариев запускаются командой:

```powershell
python -m unittest -v
```

Более строгий прогон, где предупреждения об утечках ресурсов считаются ошибками:

```powershell
python -W error::ResourceWarning -m unittest -v
```

Тесты проверяют создание БД, начальные данные, связь справочников через `city_id`, отсутствие id в таблицах интерфейса, сортировку чисел и дат, валидацию дат и чисел, мягкое удаление, историю изменений, восстановление SQLite-соединения, блокировку базы и массовые CRUD-сценарии.
